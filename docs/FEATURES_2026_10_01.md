## Data and service boundaries

- App version is `1.1.0+5`; new snapshots are schema 14 / rules `2026.5` / content
  `2026.4.0`. Content validation requires minimum client `1.1.0` for the new rules.
  Previous content assets and old formula branches remain available.
- SQLite schema 7 adds a separate archive table and stores cloud conflict revisions.
  Career journals are bounded to 40 entries per kind; archives are explicit, with a
  40-record limit rather than eviction of existing records.
- Career commits precede UI publication. Generation guards reject obsolete choices;
  cloud downloads only fill still-empty slots. Upload acknowledgments retain the
  correct cloud base if another local week commits during a request. Cloud-deletion
  conflicts preserve an absent remote snapshot and delete only the reviewed
  career/revision. Repeated conflict IDs update one pending comparison and resolve
  legacy duplicates together. Destructive slot changes wait for an existing sync,
  refuse unresolved conflicts, and validate the career/revision reviewed by the
  user. Cloud replacements also check the session inside the SQLite transaction.
- Session guards cover credential reads, HTTP dispatch, response handling, and
  background mutations. Cloud bases are account-specific; local careers survive
  account changes/deletion. Archive ownership prevents deletion against another
  account's cloud copy, and a stale Hall refresh cannot resurrect a just-deleted
  record.
- The backend validates durable fields and derives scores/metrics. Friends expose
  limited career summaries only with accepted friendship plus both users' separate
  consent. Guest feedback excludes full saves, names, account tokens and stacks.
  Unedited report retries reuse the exact reviewed body/ID; acknowledgments cannot
  erase a newer report draft after the user reopens Support.
- Challenge fairness covers standardized progression and authoritative replay,
  not unverifiable human play: choices can be reconstructed locally before the
  one final submission. There are no prizes or paid progression advantages in this
  mode. Partial challenge progress is device-local; enrollment/final score are cloud
  records. A new device can resume the enrollment but cannot recover another
  device's unsubmitted transcript.
- Backend migration `010_elevenward_career_social.sql` is append-only. Its Docker
  build compiles the exact SHA-pinned pure-Dart source into a Linux AOT helper.
  Missing/unavailable replay returns a service error rather than trusting a
  client-supplied score. CI builds that image and runs actual PostgreSQL/API/replay
  integration scripts.

## Release gates

A local implementation/test result does not establish production deployment,
Apple/Google authentication on a physical device, multi-device acceptance,
store-purchase sandbox qualification, or App Store approval. New online routes
require deploying the reviewed backend branch before a production app release
with these features. Signed remote content needs the existing trusted release keys;
none were created or replaced. The historical 100k-career proof belongs to earlier
rules: the new-rules 100k release gate remains distinct from this 1,000-career
implementation sweep.
