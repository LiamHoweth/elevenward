# Ten gameplay presentation improvements — 2026-10-01

The ten requested improvements are integrated into the existing Flutter app.
Eleven agents handled implementation, native capture, and independent review;
the integration owner reviewed and verified the combined changes. Existing
uncommitted work and saved-career identities were preserved.

## Delivered behavior

| Improvement | Behavior |
| --- | --- |
| Map labels | Localized country names appear at readable zoom levels. Labels use screen coordinates, cached landmass anchors, and collision checks. |
| Map search | Search countries in the selected language or club names, focus a country, and open a club's actual league. Accent-insensitive matching, empty results, and keyboard dismissal are supported. |
| Map controls | Accessible zoom in, zoom out, and reset buttons complement existing pinch, drag, and country selection. |
| Recent ratings | Player and career views show the five latest actual appearances, numeric ratings, and a 0–10 trend line. Journal order remains correct across season boundaries. |
| Favorite training | Explicitly save, replace, apply, or remove a favorite focus and load. Apply updates the actual weekly choice and preview; storage failures retain retry controls. |
| Offer comparison | Expand an offer to compare saved wage, promised role, actual league membership, and tactical fit with the current contract. Unknown legacy information remains unavailable. |
| Stat explanations | Tap manager trust, form, tactical fit, or legacy score help. Localized, scrollable explanations follow the career's pinned rules. |
| Journal filters | Switch between all history, matches, or decisions, then filter matches by competition. Filters preserve stored history and reset appropriately when careers change. |
| World bookmarks | Favorite clubs and leagues, then open them from quick links on the World hub. Links are filtered against the pinned world and actual league participants. |
| Fitness guidance | Show the exact projected fitness before/after and a descriptive Low, Moderate, or High range. Copy does not promise selection or an injury outcome. |

## Architecture and data

Device-local preferences use the existing SQLite store and controller:
`ui.trainingPreset`, `ui.favoriteClubIds`, and `ui.favoriteLeagueIds`. Loads and
writes share a serialized queue; the controller publishes only after persistence
succeeds. No gameplay formula, career schema, content pin, reward, account
consent, or backend service was added by this polish batch.

Reusable presentation is in `widgets/recent_performance_strip.dart`,
`training_preset_panel.dart`, `transfer_comparison_panel.dart`,
`stat_explanation.dart`, and `fitness_guidance.dart`. The controller owns durable
preferences, GameScreen owns applying the weekly choice, and the existing core
engine owns previews and calculations. Fitness bands (<50, 50–79, and ≥80) are
presentation ranges, not new simulation thresholds.

The map keeps its existing public widget API and gesture behavior. Country
labels observe display-mode changes, and zoom animation respects reduced motion.
World search preserves the typed query when the native Search action dismisses
the keyboard. Narrow layouts give club and league names full-width text below
bookmark controls. Large-text Player metrics use one column, and journal
competition selectors use wrapping radio rows so complete names remain readable.
Training load controls reuse the existing translations, retain their selected
semantics and callbacks, and use at least 48px touch targets. They remain a row
at normal sizes and stack at narrow widths or large text sizes.

## Release limits

These changes improve the app's local presentation and interaction quality.
Simulator screenshots and an unsigned optimized iOS build do not establish
physical-device or store acceptance. The existing backend deployment, protected
signing/trust configuration, exact-release-revision hosted verification,
native-language editorial review, device accessibility/account/sync/purchase
matrix, and store approval gates remain separate. See
`FEATURES_2026_10_01.md`, `ENGAGEMENT_RELEASE_READINESS.md`, and the release
runbook. No production deployment, store upload, physical-device install, or
Git publication was performed for this batch.
